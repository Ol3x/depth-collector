# ToF-360

- Dataset: `COLE-Ricoh/ToF-360`
- Reviewed: 2026-03-27
- Hugging Face: https://huggingface.co/datasets/COLE-Ricoh/ToF-360
- Domain: indoor, real
- Projection: equirectangular panoramic RGB-D
- Scale signal: small
- Geometry assessment: promising and strategically distinctive
- Artifact risk: unknown; missing values are explicitly encoded as zero
- Canonical conversion difficulty: medium to high because of spherical projection handling
- License on HF card: CC-BY-NC-SA-4.0
- Status: implemented
- Priority tier: P1
- Why it matters: strong testbed for camera-model diversity and indoor panoramic geometry
- Known issues: small dataset; viewer not automatically configured on HF
- HF packaging notes: card documents per-scene modality folders rather than a standardized HF viewer layout
- Pipeline notes: likely the cleanest early non-pinhole path because ERP ray directions can be derived analytically and depth is already described as camera-center distance

## Current Pipeline Status

- The repository now includes an initial `ToF360Pipeline`.
- The current implementation treats one scene folder as the complete download unit.
- Download is HF-backed and materializes only the configured scene's `rgb/` and `depth/` folders.
- There is no archive extraction stage in the current implementation.

## Minimum Readable Selection

- `selection: "minimum_readable"` means one scene folder from the ordered scene pool.
- That scene must still contain at least one readable sample with:
  - an RGB frame under `rgb/`
  - a paired depth frame under `depth/`
  - the spherical camera model needed to derive canonical `ray_dir`
- `selection: "all"` means all selected or discovered scenes.
- A ratio in `(0, 1]` means the corresponding prefix of the ordered scene pool.

## Current Assumptions

- RGB is read from a scene-local `rgb/` directory.
- Depth is read from a scene-local `depth/` directory.
- Depth PNGs are interpreted as 16-bit camera-center distance with a default divisor of `512.0`.
- Missing depth value `0` is currently mapped to `max_dist` by default, with a config option to reject such frames instead.
- The current implementation uses the shared equirectangular ray generator in canonical camera coordinates.
